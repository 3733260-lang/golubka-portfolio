# Портфолио Оксаны Голубевой — техническая справка (обновление)

Прикрепи этот файл в начале нового чата вместе с последним архивом `portfolio-site.zip` — так не придётся заново подбирать отступы, цвета и объяснять структуру.

## Контекст
Мультистраничный статичный сайт-портфолио (HTML/CSS/JS, без сборщиков), хостится на GitHub Pages. Главная + 4 кейса. Работаем через `create_file`/`str_replace`/`bash_tool`, картинки — через PIL (resize + сжатие + пересохранение в jpg).

## Правило работы (важно!)
Оксана присылает правки текстом, часто пачками. **Применяю правки только по явной команде** — раньше это было слово «редактируй», сейчас — универсально: жду прямого сигнала «давай применяй» / «редактируй» / когда она говорит, что список правок закончен. **Пересобираю и присылаю финальный zip-архив только когда она явно об этом просит** — не после каждой мелкой правки. Был инцидент, когда я пересобрала архив раньше, чем она закончила диктовать список правок — это разозлило, поэтому: правки → фиксирую/применяю в коде → коммичу в git локально → **жду отдельного сигнала на сборку архива**, не тороплюсь показывать результат.

Она не любит долгих пересборок «на глаз» — если координаты/отступы не даны точно, лучше спросить точные цифры, а не гадать.

## Известные технические грабли
1. **Тестовый рендерер (`wkhtmltoimage`, старый QtWebKit) неоднократно врал** — не поддерживает: CSS Grid (`display:grid`+`gap`), Flexbox `gap`, `inset` (shorthand), `aspect-ratio`, CSS `height` на внешних `<img src=".svg">`. Все эти вещи РАБОТАЮТ в реальных браузерах (Chrome/Firefox/Safari), но в тестовом скрипте рендерятся неправильно/пусто. Если что-то «должно работать, но на скрине не работает» — сначала проверить изолированным тестом, не спешить чинить несуществующий баг.
2. **Позиционирование через `position:absolute`** считает отступы от края padding, а не border.
3. **PNG с прозрачностью** → в JPEG конвертировать ТОЛЬКО через явное сведение на фон (`Image.new + paste(mask=alpha)`), никогда `.convert('RGB')` напрямую — иначе прозрачные пиксели становятся чёрными. Проверять `alpha.min() < 255` перед конвертацией.
4. **Неразрывные пробелы (`\xa0`)** — на сайте применено типографское правило «висячих предлогов» (BeautifulSoup-скрипт), из-за этого `str_replace` с обычным текстом часто не находит совпадение — искать точный текст через `python3 -c "print(repr(...))"` перед заменой.
5. **RAR-архивы от Оксаны иногда содержат повреждённые файлы** (0 байт) — сразу проверять `wc -c` после распаковки, не тратить время на догадки.
6. **Дублирующиеся HTML-теги** — несколько раз находились случайно задвоенные `<header>`, `<footer>`, `</div>` (скорее всего, артефакты более ранних правок через `str_replace`) — при подозрении на «крива вёрстка без причины» проверять баланس тегов: `grep -o '<div' file | wc -l` vs `grep -o '</div>' file | wc -l` (не забывать, что `<p>` без атрибутов не матчится паттерном `<p `, считать и `<p>`, и `<p `).
7. **Git инициализируется в рабочей папке контейнера** — это разово помогает откатывать правки в течение одной сессии, но **не переживает сброс окружения** (сброс уже случался несколько раз за проект). Единственная надёжная защита — архив, который Оксана хранит у себя, и обновлённый файл-хендофф (этот файл).
8. **Размер архива важен** — Оксана однажды не смогла скачать файл из-за веса (~54МБ). Держать галерейные/декоративные изображения сжатыми (JPEG quality ~65-70, ширина ~1000px для превью-галерей), не заливать в максимальном качестве без необходимости.
